# 下一批只读能力设计记录

若优先级问卷仍未答复，06:00后首先推进生物和掉落物观察。这里只登记设计与源码发现，不把尚未实现路径放进能力目录。

## 原生入口与范围

API1.9.3.2的 SubsystemBodies.Bodies 是已登记 ComponentBody 集合；FindBodiesInArea 使用8格分区，并包含边界附近分区，必须再按请求的三维范围精确过滤。不能把其返回数量当作全世界生物数量。SubsystemPickables.Pickables 仅表示当前活动掉落物，其内部读取有锁；后台线程不能持有游戏对象。

实体观察拟返回种类、原生模板名称、当前位置／速度、健康和玩家身份（存在时）。范围体积上限100万格，响应分页至多64项；单次扫描还需活动对象数量上限，超出应明确报告限额，不能静默截断后宣称查询完整。首版观察标识仅在当前boot/session有效，不能作为后续修改授权。

掉落物观察拟返回完整物品值、数量、位置、速度及当前原生编号。编号不是跨重启稳定身份。列表可能跨帧变化，需声明观察时间；若实现稳定分页，应在游戏线程一次采集纯数据快照，再以短期游标分页，不在页与页之间依赖可变集合索引。

查询前核验目标与选定玩家，以及区域实际加载状态。未加载区域不能返回“没有生物／掉落物”。即使区块有效，也明确只观察当前活动对象，不含未生成、休眠或Mod自定义对象；entityexist/dropexist 的适配判定只能在该范围内解释。

## 测试顺序

1. 纯输入检查：逆序／超限范围、非法游标、页上限、未知子类型、错误玩家。
2. 实验世界基线备份；有限内部夹具生成一种固定生物与固定物品掉落，夹具不进入MCP。
3. 捕获并验证种类、值、数量、包含端点及三维过滤；单页和分页一致。
4. 当前世界为空／目标错误／未加载区域／对象在分页期间移动或消失／双客户端游标隔离。
5. 清理仅由夹具登记的对象，保存重载并核对没有残留；不得按物种批量删除其他对象。
6. 原生副作用不明确的条件，例如 creaturedie、clickinteract，不跟随此次只读工具开放；另行设计事件游标、是否消费和恢复语义。

若用户改选环境或玩家写入，先提出具体恢复契约：持久配置和瞬时天气／生理状态分开，前后值比较拒绝冲突；不承诺倒转已经发生的饥饿、伤害、实体交互或天气效果。只有通过实验世界验证的路径才能登记可用。
